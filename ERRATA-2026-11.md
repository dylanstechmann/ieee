## Sealed packages

### `derived/dynamics-v9/` (its report is also pinned by `share/Robot-Studio-v8.html`)

November 4 review. A Python port reproduces this package exactly, and full-command runs of that port exposed faults in the model behind it, `tools/mule-dynamics-v5.js`. The sealed files stay unchanged. For anything beyond gentle cruise, use the corrected model and `derived/envelope-v10/`.

| Statement | Correction |
|---|---|
| `brake-hold`: 89 saturated samples, 3 A, 0.270 m/s slip, 0.0273 Wh | These describe a numerical oscillation, not braking. A slipping wheel's motor time constant (about 2.1 ms) is half the 4.17 ms step, the stability limit, so after the stop command the wheel flips between +6.9 and −7.7 rad/s every step at ±3 A. The corrected model stops cleanly: 0 saturated samples, 0.018 m/s slip, 0.0017 Wh. |
| `asymmetric-traction` final yaw error 0.389 rad; `encoder-dropout` 0.120 rad, final speed 0.231 m/s | Once a wheel slips in this model, the slip never closes, so these errors persist to the end of the run. With slip able to recover, both end near 0 rad and 0.203 m/s. For the same reason a full-command run locks at 0.374 m/s instead of reaching about 0.62 m/s. |
| `low-voltage` scenario and the 9–12 V sensitivity range | Duty is scaled by the supply voltage, which cancels it, so these test only sag. Top speed does not fall with voltage; at full command, 9 V even comes out faster than 12 V. The published cruise numbers are nearly unaffected, because cruise never reaches full duty. |
| Sensitivity rows list friction from 0.15 to 0.5 | The model never reads that value, so all 48 rows ran at friction 0.35. Re-running them with the recorded value applied changes no metric, because cruise stays under the grip limit. |
| Cruise current about 0.116 A | Leaves out the motor's 0.2 A no-load current, listed in the archived Pololu page. The corrected model gives about 0.31 A. |
